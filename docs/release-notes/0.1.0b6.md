# Seex 0.1.0b6

Seex 0.1.0b6 is the first release with the bounded native storage and Viewer
contracts. It moves the local store to append-only v5, makes SQLite WAL plus
local DuckLake the only storage combination, and cuts the Viewer Detail path
down to the visible viewport. Cargo package `0.1.0-beta.6`, Python package
`0.1.0b6`, and tag `v0.1.0-beta.6` identify the same source.

## Install

```console
pip install seex==0.1.0b6
cargo add seex@0.1.0-beta.6
brew install reformovo/tap/seex-app
```

## Viewer and curve reads

- Detail now reads only the visible viewport. An empty viewport draws no curve,
  and a sparse curve starts and ends at its first and last in-viewport
  observation. The Viewer no longer retains out-of-viewport neighbor points just
  to draw edge segments.
- Detail and Overview use one filtered sampling SQL shape: Run, metric, and Step
  range in one CTE, non-finite values filtered before sampling, and rows ordered
  by Step. `source_count` reports finite observations in the requested range;
  an empty range returns zero observations.
- Reduced curves use the bundled Seex-native LTTB selector. The Viewer is
  Step-only, each curve is limited to 1,024 real points, and one panel is
  limited to 16 overlaid Runs. The Elapsed time axis item is visible but
  disabled; its app-menu entry and action were removed. Workbench files that
  still encode the elapsed-time axis must be switched back to Step.
- The panel point budget is fixed at 1,024 points. Resizing no longer changes
  sampling density or refetches a curve; use Refresh after external writes.
- Finished-only metric summaries no longer read Parquet facts. A small catalog
  status check keeps the running-Run fact fallback only for summaries that need
  it.
- Curve completeness now follows Run lifecycle only: Finished is `Complete`,
  Running is `Partial` with `RunRunning`, and Failed is `Partial` with
  `RunFailed`. A Run without the requested metric is `Complete` with zero
  points. The curve path no longer emits `Invalid`, `Unavailable`,
  `NegativeAxis`, `DecreasingAxis`, `NonFiniteValue`, or
  `DiagnosticsUnavailable`.
- Series diagnostics and their caches were removed. The aligned
  (`AlignedMetricPoint`) and overview-specific desktop query surfaces were also
  removed. The bounded desktop query path is the supported chart API.
- `MAX_SELECTED_RUNS` is now 16. Archived Runs and unavailable references do not
  consume selection capacity; only visible catalog Runs do.

## Storage and SDK

- Native v5 is append-only. Every repeated Step observation is retained, queries
  and summaries no longer select a last-write-wins value, and no ordering is
  promised between observations of the same Step. Summaries count all
  observations.
- The first release store is local-only: SQLite WAL catalog with
  DuckLake-managed local data. Legacy DuckDB catalogs, S3 data paths, and older
  store formats are rejected at the public entry points without migration.
- Different Runs may be written by different processes at the same time. A
  single Run still has one writer. Catalog write transactions are serialized
  with a short project-level lock, pending flushes recover on writer restart,
  and Readers refresh DuckLake snapshots across flushes.
- A terminal call flushes the Run's pending observations before the Run is
  marked Finished or Failed. If that flush fails, the Run stays Running and the
  terminal call can be retried; a Reader never sees a terminal Run whose data
  has not been published.
- Run discovery uses an indexed catalog with stable cursor pages; metric keys
  use exact lookup and indexed prefix pages; the series directory publishes only
  sequences that exist. Reader caches are bounded.
- The shared-sorted file layout was evaluated and selected as a direction, but
  the production layout has not switched to it. DuckLake remains the owner of
  fact snapshots and file manifests.
- The Python surface is now limited to Run creation, logging, finishing, the
  context manager, Settings, and write diagnostics. Read/query, Arrow,
  comparison, ranking, and standalone CLI surfaces were removed.

## Breaking changes

- Native stores from before v5 are rejected; there is no migration path.
- The local SQLite plus DuckLake combination replaces the former DuckDB catalog
  and S3-compatible data paths.
- Chart reads are Step-only; the Elapsed time axis is disabled.
- The Python read/query surface and the aligned/diagnostics Rust surfaces were
  removed.
- The Viewer allows at most 16 overlaid Runs and 1,024 points per curve.
- `source_count` now means finite observations in the requested range, not the
  raw physical row count.

The Parquet schema remains the long-term compatibility boundary.

## Performance evidence

The viewport-only Detail change was measured against the previous
neighbor-retaining revision with one bounded ABBA workload: prefix 52.11% faster,
mid-viewport 44.36% faster, and outside-viewport 79.48% faster (MAD 0.32-1.87%).
This is the only production speedup claimed for this release.

Overview and the single filtered SQL were not proven faster. The retained
performance report measures roughly 683-694 ms for a 16-curve Overview request,
with about 32-44 ms of fixed per-panel cost. The finished-only summary change is
plan-level evidence (zero Parquet files), not an ABBA result.

The release does not claim measured desktop FPS or RSS. Those remain manual
qualification items for the macOS Viewer.
