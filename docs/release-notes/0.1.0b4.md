# Seex 0.1.0b4

Seex 0.1.0b4 improves Viewer elapsed-time alignment, progressive curve loading,
and local native reads. Cargo package `0.1.0-beta.4`, Python package
`0.1.0b4`, and tag `v0.1.0-beta.4` identify the same source.

## Install

```console
pip install seex==0.1.0b4
cargo add seex@0.1.0-beta.4
brew install reformovo/tap/seex-app
```

## Viewer

- Elapsed time aligns Runs by time since each Run started. Switching axes
  clears cursors whose coordinates belong to the previous axis.
- The active View loads Overview curves one Run at a time and publishes each
  result immediately. Visible Metrics share progress fairly; inactive Views
  release query-derived state.
- Detail loads for visible rows after Overview coverage, with higher density
  for selected and hovered Metrics. Navigation reuses Detail while it covers
  the requested viewport and otherwise displays an Overview preview.
- Leaving rows, switching Views, and superseding navigation cancel obsolete
  reads. Pointer movement avoids synchronizing all child curve snapshots.

## Native storage

- Viewer workers share a local DuckDB database with separate read connections.
  Full-range reduction streams ordered rows and retains bounded real-sample
  extrema when diagnostics permit; other queries retain their SQL plan.
- Shared local Viewer reads disable DuckDB's external file cache. Ordinary
  Reader and writer databases retain the default cache behavior.
- SQLite catalogs support one writer process and multiple read-only Readers
  through WAL and a 30-second metadata busy timeout. Opening an older
  DELETE-journal catalog with a writer enables WAL; migration failure is
  reported. Readers do not change the journal mode.

## Compatibility and known limits

- Workbench schema version remains 1, but the elapsed-time axis is encoded as
  `elapsed_time`. Old Workbench documents containing `axis = "timestamp"` are
  rejected and are not migrated automatically. Recreate those Workbench views
  rather than reusing absolute-timestamp viewport coordinates.
- SQLite WAL support does not add multiple-writer coordination. The default
  DuckDB catalog still has the independent-reader/active-writer limitation.
- Large repeated-zoom workloads can still exceed the memory and duration
  targets. The 10-Run, six-Metric, one-million-point, 30-zoom diagnostic exceeded
  120 seconds and reached 2,093,875,200 bytes peak RSS with the disabled cache.
  These remain known performance limits; see the
  [performance validation record](../reference/viewer-performance-validation.md).
- The Parquet schema remains unchanged. Pre-1.0 releases retain the existing
  experimental compatibility policy.

## Validation

Regression coverage includes elapsed-time behavior, progressive scheduling,
viewport reuse, stale-result cancellation, bounded reductions, and a SQLite
writer with four preopened Reader processes. Release qualification also checks
Rust and Python tests, formatting, lint, types, package identities, native
artifacts, and the macOS app bundle signature and icon.
